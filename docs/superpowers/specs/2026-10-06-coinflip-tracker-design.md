# CoinFlipTracker 设计规格（Spec）

日期：2026-10-06
状态：待用户审阅

## 1. 概述

为《游戏王 Master Duel》构建一个 Windows 桌面程序，手动记录每局决斗的硬币输赢、先后手与决斗胜负，并长期统计当天与累计数据，包括连串（streak）与趋势图表。

参考对象：Untapped 的 coin flip tracker（手动逐局录入 + 胜率/streak/当天与累计统计 + 图表）。

已确认的领域规则（用户确认）：Master Duel 中硬币胜者**可以选择**先手或后手，因此"硬币输赢"与"先后手"是两个独立字段。

## 2. 需求

### 功能需求
- 逐局录入：硬币赢/输、先手/后手、决斗胜/负（三项均为必填才允许保存），可选备注。
- 统计展示：当天与累计两组，各自包含
  - 总对数、硬币赢/输次数与胜率
  - 先手/后手次数与占比
  - 决斗胜/负次数与胜率
  - 硬币当前连串（连赢或连输）与历史最长连串
  - 决斗当前连胜/连负与历史最长连胜/连负
- 趋势图表（matplotlib）：按日硬币胜率曲线、按日对数柱状图。
- 数据长期保存，程序重启后不丢失。

### 明确不做（YAGNI）
- 数据导出（CSV/JSON）——后续可加
- 卡组/对手维度统计
- 云同步、多设备、多用户
- 自动读取游戏数据——可行性 spike 已验证不可行：本机 `LocalSave/` 仅 UI 设置、`LocalData/` 为资源缓存，无回放数据；Konami 官方 API 不含硬币结果（Untapped 的硬币追踪同为手动）。若后续尝试屏幕识别自动化，作为独立子项目另行设计。

## 3. 关键定义

- **当天**：以录入时刻的本地系统日期（`date`）分组。
- **硬币胜率** = 硬币赢次数 / 总对数。
- **先手占比** = 先手次数 / 总对数。
- **当前连串**：从最近一条记录向前连续同结果（赢或输）的长度；无数据时为 0。
- **最长连串**：全部历史中连续同结果的最大长度。
- 决斗胜负连串同理，独立于硬币连串计算。

## 4. 架构

单进程 Python 桌面应用，模块划分如下，每个模块单一职责、可独立测试：

```
CoinFlipTracker/
  main.py          # 入口：初始化存储，启动 UI
  storage.py       # SQLite 存取：建表、插入、按日期聚合查询
  stats.py         # 纯计算函数：计数、胜率、连串（不依赖数据库）
  charts.py        # matplotlib 图表生成
  ui.py            # tkinter 主窗口：录入面板 + 统计面板 + 图表标签页
  tests/           # unittest 单元测试
  data/            # SQLite 数据库文件（不提交到 git）
  requirements.txt # matplotlib
  README.md
```

依赖：Python 3.13（标准库 `sqlite3`、`tkinter`、`unittest`）+ `matplotlib`（唯一第三方依赖）。

数据流：用户点击录入 → `ui.py` 收集三项选择 → `storage.py` 插入一条记录 → `stats.py` 基于查询结果计算统计 → `ui.py` 刷新显示 → `charts.py` 刷新图表。

## 5. 数据模型

`duels` 表：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY | 自增 |
| created_at | TEXT | ISO 8601 时间戳 |
| date | TEXT | 本地日期 YYYY-MM-DD，用于按日聚合 |
| coin_win | INTEGER | 1=硬币赢，0=输 |
| went_first | INTEGER | 1=先手，0=后手 |
| duel_win | INTEGER | 1=决斗胜，0=负 |
| note | TEXT | 可选备注 |

索引：`idx_duels_date (date)`。

## 6. 模块设计

### storage.py
- `init_db(path)`：创建数据库与表（幂等），启用 WAL 模式。
- `insert_duel(coin_win, went_first, duel_win, note=None)`：插入记录。
- `get_all()` / `get_by_date(date)` / `get_daily_counts()`：供统计与图表使用。
- 返回记录为普通 dict 列表，便于 `stats.py` 纯函数处理。

### stats.py
- 纯函数，输入记录列表，输出统计 dict：计数、胜率、占比、当前/最长连串（硬币与决斗各自）。
- 无数据库依赖，全部可单元测试。

### charts.py
- 输入按日聚合数据，输出 matplotlib Figure。
- 两张图：按日硬币胜率折线、按日对数柱状。
- 数据为空时返回占位提示图。

### ui.py
- 主窗口布局：
  - 录入区：三组按钮（硬币赢/输、先手/后手、胜/负），选中高亮；三项齐全后"保存"按钮启用；保存后清空选择并刷新统计。
  - 统计区：当天卡片 + 累计卡片。
  - 图表区：标签页切换两张趋势图。
- 键盘快捷键：1/2 硬币赢/输，3/4 先手/后手，5/6 胜/负，Enter 保存。
- matplotlib 嵌入 tkinter（`Figure` 转图片或 `matplotlib.backends`），若导入失败则图表区显示提示文本，其余功能不受影响。

### main.py
- 解析可选 `--db` 参数（默认 `data/duels.db`），初始化存储，启动 UI。

## 7. 错误处理

- 数据库文件/目录不存在：启动时自动创建。
- 数据库损坏或打开失败：报错退出并提示删除/备份 `data/duels.db`。
- 录入不完整：保存按钮禁用，不允许写入。
- 无数据：统计显示 0，图表显示占位提示。
- matplotlib 不可用：图表区降级为文本提示，核心录入/统计功能正常。

## 8. 测试策略

- `stats.py`：连串与胜率单元测试（空数据、全赢、交替、混合边界）。
- `storage.py`：临时数据库（`tempfile`）验证插入与按日聚合。
- `charts.py`：冒烟测试（生成 Figure 不抛异常）。
- `ui.py`：手动冒烟测试（录入→保存→统计更新→图表刷新）。

## 9. 验收标准

1. 首次运行自动创建数据库，录入 3 条记录后当天统计正确。
2. 重启程序后累计统计包含历史数据。
3. 连串计算与手工验证一致（例如 WWLLW → 当前连赢 1，最长连赢 2）。
4. 图表标签页显示按日趋势；无数据时不崩溃。
