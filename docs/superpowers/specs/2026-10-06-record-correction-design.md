# CoinFlipTracker 记录纠错功能 设计规格（Spec）

日期：2026-10-06
状态：待用户审阅

> 本 spec 扩展 `2026-10-06-coinflip-tracker-design.md`。其中 §6 关于 `charts.py` 的
> 「返回 Figure」描述已被「绘制到调用方传入的 Axes」取代（见 commit 8df2744、dc37842）。

## 概述

手动录入必然出错：硬币输赢选反、先后手选反、决斗结果选反、漏录、补录到错误日期。
本功能让用户能**撤销上一条录入**，并在**记录列表**里就地编辑或删除任意一条记录，
使统计结果始终与真实对局一致。

## 需求

1. **撤销上一条**：删除最近一次录入的记录，可连续撤销。
2. **记录列表**：新增标签页，列出记录（日期、录入时间、硬币、先后手、决斗、备注），支持按日期筛选。
3. **就地编辑**：选中一条记录后，修改其硬币/先后手/决斗/备注/日期，写回数据库。
4. **删除任意记录**：从列表删除选中记录。
5. **补录日期**：录入区新增日期输入框，默认当天，允许指定历史日期。
6. **错误提示**：非法日期、记录不存在、无记录可撤销等情况给出明确提示，不崩溃。

### 明确不做（YAGNI）

- 批量编辑、搜索、分页、导出
- 修改历史 / 审计日志 / 软删除
- 撤销栈（只撤销「最近一条」，不做多步 redo）
- 编辑 `created_at`（录入时间不可改）
- 删除/更新前的二次确认对话框（列表里选中即可见，误操作可重新录入）
- 自动检测可疑录入（例如同一日期重复记录）

## 关键定义

- **「上一条」**：`id` 最大的记录，即最近一次插入的记录 —— 与录入顺序一致，与 `date` 字段无关。
- **`date` vs `created_at`**：`date` 是「这场对局发生在哪天」（可被补录或编辑），`created_at` 是「这条记录何时被录入」（不可改）。统计按 `date` 分组。
- **选中记录**：列表中当前高亮的行，其 `iid` 即记录 `id`。编辑面板只作用于选中记录。

## 架构

沿用现有三层结构，不新增模块：

```
main.py  →  ui.py  →  storage.py  →  SQLite (data/duels.db)
```

- `storage.py`：新增 update / delete / 查询接口，是数据校验的唯一权威。
- `ui.py`：新增「记录列表」标签页与录入区的两个控件；所有交互最终调用 storage。
- `stats.py` / `charts.py`：无需改动 —— 它们接收记录列表，纠错后数据自然变化。

数据模型不变（无 schema 迁移），`duels` 表结构保持原样。

## 组件设计

### storage.py 新增接口

```python
def get_records(self, date: str | None = None) -> list[dict]:
    """按 id 倒序（最新在前）返回记录；date 为 None 时返回全部。"""

def get_dates(self) -> list[str]:
    """返回所有出现过的日期，倒序（用于筛选下拉框）。"""

def update_duel(self, duel_id: int, coin_win: int, went_first: int,
                duel_win: int, note: str | None, date: str) -> bool:
    """更新指定记录；返回是否命中。非法日期抛 ValueError，非法 flag 抛 sqlite3.IntegrityError。"""

def delete_duel(self, duel_id: int) -> bool:
    """删除指定记录；返回是否命中。"""

def delete_last(self) -> int | None:
    """删除 id 最大的记录，返回被删除的 id；表为空时返回 None。"""
```

日期校验集中在 `_validate_date(value)`（`datetime.strptime(value, "%Y-%m-%d")`，失败抛 `ValueError`），
`insert_duel` 与 `update_duel` 都调用它。现有 `insert_duel` 因此新增一条校验行为：传入
`"2026-13-40"` 之类的字符串不再静默写入。

### ui.py 录入区（顶部）

新增两个控件：

- `self.date_entry`：日期输入框，默认值为当天，宽度 10。
- `self.undo_btn`：「撤销上一条」按钮，绑定 `Ctrl+Z`。

`save()` 读取 `date_entry`，校验失败则不保存并提示；成功则传入 `insert_duel(..., date=...)`。
保存后备注清空、三组选择重置，但日期保持不变 —— 补录同一天的多局时不必重复输入。

### ui.py 「记录列表」标签页

自上而下：

1. **筛选行**：`ttk.Combobox`（`state="readonly"`，值为 `["全部"] + get_dates()`）+ 计数标签「共 N 条」。
2. **表格**：`ttk.Treeview`，`show="headings"`，列 `日期 | 时间 | 硬币 | 先后手 | 决斗 | 备注`；
   行 `iid` 为记录 id 的字符串；时间显示 `created_at` 的 `HH:MM`。
3. **编辑面板**：三组按钮（硬币/先后手/决斗，复用 `_make_choice_group`）+ 备注输入 + 日期输入 +
   `[更新] [删除] [取消]`。未选中记录时三个按钮禁用。

抽取 `_make_choice_group(parent, field, choices, store)` 供录入区与编辑面板共用，避免重复代码：
它创建三组按钮、把选择写入传入的 `store` 字典，并返回 `{value: button}`；高亮逻辑抽为
`_highlight(store, buttons, field, value)`。`self.selections`（录入）与 `self.edit_selections`（编辑）
各自独立，互不影响。

### 交互流程

- **选中行** → 编辑面板填充该记录的值，按钮启用。
- **更新** → 校验日期 → `update_duel(...)` → 返回 False 则提示「该记录已不存在」 → `refresh()` → 若记录仍在，重新选中它。
- **删除** → `delete_duel(id)` → `refresh()` → 编辑面板清空并禁用。
- **撤销上一条** → `delete_last()` → 返回 None 则提示「没有可撤销的记录」 → `refresh()`。
- **取消** → 清空编辑面板并禁用，不写数据库。
- **筛选变化** → 重新加载表格行；若当前选中行不在筛选结果内，清空编辑面板。

`refresh()` 现在更新：当天/累计统计、三张图表、列表内容、筛选下拉框的日期选项。

### Enter 与快捷键

- `<Return>`：仅当当前标签页不是「记录列表」时触发 `save()`；在列表标签页内按 Enter 不做任何事（避免误保存）。
- 数字快捷键（1–6）：当焦点在输入框（`tk.Entry`）内时不触发。现有实现存在缺陷 —— 在备注框输入数字会同时触发快捷键，
  例如输入 `1` 会把「硬币」选成「赢」，静默改变当前选择（1–6 都是合法值，不会抛 `IntegrityError`）。本功能顺带修复。
- `Ctrl+Z`：与数字快捷键同样受焦点保护 —— 焦点在文本框内时不触发，否则打字时的"撤销"反射会删掉数据库记录。
  「撤销上一条」按钮不受此限制。

## 错误处理

| 情况 | 行为 |
|---|---|
| 日期格式非法 | 不写库，提示「日期格式应为 YYYY-MM-DD」 |
| 更新/删除的 id 不存在 | 提示「该记录已不存在」，刷新列表 |
| 撤销时无记录 | 提示「没有可撤销的记录」 |
| 运行时数据库错误 | 捕获 `sqlite3.Error`，提示「数据库操作失败：{e}」，不崩溃 |
| 启动时数据库损坏 | 保持现有行为：提示后退出 |

提示统一写入 `self.message_label`（位于统计行下方），每次操作覆盖。

## 测试策略

**storage（`tests/test_storage.py`）**
- `get_records` 返回倒序；带 `date` 参数时只返回该日期
- `get_dates` 返回去重、倒序的日期；空库返回 `[]`
- `update_duel` 改字段成功；对不存在的 id 返回 False；非法日期抛 ValueError
- `delete_duel` 删除成功；不存在的 id 返回 False
- `delete_last` 删除 id 最大的记录并返回该 id；空库返回 None
- `insert_duel` 非法日期抛 ValueError

**ui（`tests/test_ui.py`）**
- 标签页共 4 个，第 4 个为「记录列表」
- 选中某行后编辑面板的值与该记录一致
- 更新写回数据库并刷新统计文本
- 删除后列表行数减少
- 撤销删除最新一条；空库时不崩溃并提示
- 筛选日期后行数正确
- 录入区指定日期 → 记录 `date` 为该日期
- 非法日期 → 不保存
- 在列表标签页按 Enter 不新增记录
- 焦点在备注框时按数字键不改变 `selections`

现有 37 个测试必须全部保持通过。

## 验收标准

1. 录错后可在列表里选中并改正，统计与图表立即更新。
2. 连续按 Ctrl+Z 可撤销多条最近录入。
3. 补录到历史日期后，「每日对数」与「硬币胜率趋势」图表正确反映该日期。
4. 非法日期、不存在的记录、空库撤销都不导致程序崩溃。
5. 在备注框输入数字不会误改选择，也不会崩溃。
